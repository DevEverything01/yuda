# ADR 0002: 混合 ASR 架构——云端豆包流式为主，SenseVoice 离线兜底

- 状态：accepted
- 日期：2026-08-23

## 背景

中文-first 是语打的全部差异化。四个核心指标互相冲突：准确率、延迟、成本、隐私/离线。

## 决策

双引擎 + 路由：

- **主力**：火山引擎豆包语音识别大模型，流式 WebSocket（中英混输、ITN、自动标点；≈ ¥2.2/小时）。
- **兜底**：sherpa-onnx + SenseVoice int8（中/英/日/韩/粤，CPU 实时），silero-vad 端点检测，模型首次使用自动下载。
- **模式**：`cloud` / `offline` / `auto`（默认 auto：云端 2 秒连接超时，失败透明切换离线并在 UI 显示「离线」徽标）。

## 理由

- 豆包大模型是中文识别准确率与方言能力的上限（豆包输入法同源能力）；SenseVoice 是中文端侧开源的上限（RK3588 级 CPU 即可实时）。
- 豆包输入法的离线模式证明：纯云端方案断网即死不可接受；兜底是硬需求。

## 被否决方案

- **Whisper 系（whisper.cpp/faster-whisper/Groq Whisper）**：英文强中文够用，但标点、中英混输、口语纠错均非为中国用户设计——全体现有 Linux 方案的同质化源头，明确弃用。
- **纯端侧**：零成本纯隐私，但准确率/方言上限低于云端大模型。
- **纯云端**：最简单最准，但断网即死、持续计费、隐私让渡。

## 影响

- ASR 抽象为 trait，后续可加阿里云等备选供应商（仅配置层扩展）。
- 离线模型约 200–300MB，首次下载需进度提示。
