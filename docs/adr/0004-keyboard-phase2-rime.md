# ADR 0004: 键盘层（Phase 2）复用 Rime 内核，自研 UI 与 LLM 智能层

- 状态：accepted
- 日期：2026-08-23

## 背景

目标产品形态是「键盘 + 语音一体化」的现代中文输入法（对标豆包输入法）。需要决定拼音引擎自研还是复用。

## 决策

Phase 2 键盘层 = fcitx5 框架 + Rime 内核（雾凇拼音词库 + 万象语法模型）+ **自研现代候选窗 UI** + **自研 LLM 纠错/联想智能层**。不自研拼音引擎。

## 理由

- Rime 即跨平台内核：鼠须管（macOS）/小狼毫（Windows）/同文（Android）都是它的壳，Linux 即 fcitx5-rime；引擎层经过十几年验证。
- 豆包键盘层的真正壁垒是 LLM 语义纠错/联想（云端智能层），不是引擎；自建等效智能层才是差异化。
- 用户对 fcitx5 的实际痛点（候选框飞出终端外、拼音渲染不出汉字）全是前端 UI/协议层问题（fcitx5#821、Hyprland#6179 同类），恰好在自研 UI 的射程内。
- 从零自研拼音引擎以年计；鼠须管模式以月计，且无人指责鼠须管「拼凑」。

## 被否决方案

- **从零自研拼音引擎**：周期以年计，无差异化收益。
- **fork Rime 深度改造**：工作量翻倍，收益不明确；如引擎行为确需改动再单独立 ADR。
- **只做语音层不做键盘**：与已锁定的产品目标（一体化现代体验）冲突。

## 影响

- Phase 2 开工前先做 3 天 spike：验证 fcitx5 classicui 替换 / input-method-v2 直连两条 UI 路线的可行性，再全量投入。
- 语音上屏届时改走 IME commit 通道，ADR 0003 的剪贴板路径降级为兼容兜底。
